# Contributor Guide

## Purpose

This project documents the concept and prototype of Vínculo.

Vínculo was developed through an iterative process combining conceptual design, prototyping, and continuous documentation.

This repository reflects both the system and the process used to build it.

---

## Project context

The project evolved through multiple iterations.

It initially began as a different system (VITRO) and was later redefined as Vínculo.  
Instead of restarting, the documentation was adapted to reflect this shift.

This means:
- documentation captures real design evolution  
- decisions are tied to iteration cycles  
- structure emerged through testing and refinement  

---

## Working process

The development of Vínculo was based on a continuous loop between:
- idea  
- prototype  
- documentation  

Each part informed the others, allowing the system to evolve through iteration rather than linear planning.

Documentation was not treated as a final step, but as an active part of the design process.

---

## Use of LLMs in the process

LLMs (Claude and ChatGPT) were used as part of an iterative thinking and writing process.

Rather than using them to generate final outputs, I used them to **externalize, structure, and refine my ideas**.

Throughout the project, I:
- maintained structured conversations where concepts, drafts, and decisions were developed  
- iterated on documentation through back-and-forth dialogue  
- used the tools to identify gaps, challenge assumptions, and improve clarity  

This created a working environment where:
- ideas were continuously revisited and refined  
- the evolution of the project remained visible  
- decisions were made with increasing clarity over time  

Using LLMs in this way helped me maintain **accountability and authorship** over the project.

They functioned as a support tool for iteration and reflection, while all final decisions, structure, and content were critically evaluated and determined by me.

This approach allowed me to better understand my own ideas by making them explicit, structured, and continuously testable.

---

## How to contribute

Contributions should focus on improving clarity and alignment with the system.

This can include:
- refining documentation language  
- improving structural consistency  
- extending or clarifying the conceptual model  
- improving the prototype  

---

## Working with the system

The project is composed of:

- conceptual documentation  
- an interactive prototype  
- iterative design decisions  

When contributing:

- respect the core rule:  
  **people do not connect directly — all connections pass through shared work**

- do not introduce features that break this model  
- ensure all additions reflect real participation, not abstraction  

---

## Notes

This project treats documentation as part of the design process, not as a final step.

The system, the prototype, and the documentation were developed together, each informing the other.
